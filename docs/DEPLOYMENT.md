# Production-развёртывание панели

Панель управляет серверными VPN-ресурсами и требует тщательно ограниченных
прав. Это пример процесса подготовки, а не универсальный installer: набор
systemd units, Docker mounts, Xray API и AmneziaWG конфигурация различаются
между VPS. Перед применением составьте точный inventory и резервную копию.

## Сеть

- Оставьте web-server на `127.0.0.1:8787`.
- Не публикуйте порт через firewall, reverse proxy или `0.0.0.0`.
- Подключайтесь SSH-туннелем с доверенного компьютера:

```powershell
ssh -N -L 8787:127.0.0.1:8787 admin@your-vps.example.net
```

## Служба и привилегии

В этом репозитории пока нет проверенного универсального production-unit или
installer. Панель может управлять systemd units, Docker, Xray API и
AmneziaWG; запуск от непривилегированного пользователя без отдельно
спроектированного helper/sudoers может ломать управление, а доступ к Docker
socket практически равносилен root. Поэтому не копируйте произвольный unit и
не запускайте панель от root без оценки угроз. Сначала составьте точный
inventory всех вызываемых команд, файлов, сокетов и операций, затем разработайте
минимальные разрешения и проверьте их на отдельном тестовом хосте.

До завершения такой проверки считайте production-развёртывание ручным и
неподдерживаемым. Не публикуйте API на `0.0.0.0`; ограничьте его loopback и
используйте SSH-туннель с доверенного компьютера.

## Сохранение и откат

Перед обновлением остановите только панель, сделайте согласованную копию
SQLite через backup API, конфигурации запуска, кода и нужных credentials.
Не останавливайте VPN-службы без причины. Откатите код, сохраняя актуальную
БД и totals; старую БД восстанавливайте только при доказанной согласованности.
Проверьте SQLite integrity, владельцев/устройства, systemd units и VPN после
операции. Храните резервные копии вне каталога, который будет заменён.

Точные production-команды зависят от вашего хоста; не копируйте команды
из диагностических заметок к отдельному серверу как installer.
