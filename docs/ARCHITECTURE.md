# Архитектура

## Компоненты

```text
Windows-лаунчер ── OpenSSH local forward ── браузер администратора
                                                │ localhost HTTP + page token
                                                ▼
                                          Python panel/server.py

Либо ручной SSH-туннель:
Браузер (локально через SSH)
       │ localhost HTTP + краткоживущий page token
       ▼
Python panel/server.py ── SQLite + локальная статика
       ├── systemd/OpenFlux services + IPC counters
       ├── Docker/Xray API and scoped credential updates
       └── Docker/AmneziaWG peer operations

OpenFlux Desktop ── локальный OpenFlux core process ── selected transport ── exit
```

Лаунчер панели и VPN-клиент — разные приложения. Исходники лаунчера находятся
в `panel-launcher/`. Он устанавливает SSH port-forward к loopback веб-панели
и открывает её в браузере; не запускает VPN-ядро и не меняет VPN-профили.
OpenFlux Desktop не соединяется с admin API
панели: ключи VPN выдаются панелью и импортируются в совместимый клиент.
Desktop хранит профили локально и запускает ядро OpenFlux как дочерний процесс.

## Backend панели

`panel/server.py` — стандартная библиотека Python `http.server`, SQLite,
без внешнего web-фреймворка. `management.py` реализует реестр устройств,
аудит и удаление; `telemetry.py` аккумулирует IPC counters; `happ.py` и
`amnezia.py` изолируют интеграции с соответствующими сервисами.
`panel/static/` — локальные HTML/CSS/JS и favicon.

По умолчанию web-server привязан к `127.0.0.1`. API отвергает запросы без
page token и проверяет Host/Origin. Это защита для SSH-туннеля, а не система
учётных записей для публичного многопользовательского сайта.

## Счётчики и состояния

- OpenFlux: счётчики берутся из IPC конкретного профиля.
- Happ и AmneziaWG: используются индивидуальные статистические значения
  соответствующего сервиса/peer, если они доступны.
- Если источник недоступен, UI сообщает об этом; не подставляется фиктивный ноль.
- Статистика наблюдательная и не предназначена для выставления счетов.

Статус работающего процесса сам по себе не подтверждает доступ к интернету.
Клиентский Windows UI показывает состояния своего процесса и транспортных
сессий по доступной ему информации.

## Изоляция данных

SQLite и индивидуальные credentials находятся в системных каталогах, не в
публичном web root. Веб-страница выдаёт профиль только в ответ на явное
действие администратора. Секрет панели не встраивается в desktop-клиент.

Текущая версия не может надёжно распознать одно физическое устройство по
скопированному Happ-ключу: протокол не предоставляет обязательную
криптографическую идентичность установки. Запрет по IP/числу соединений не
используется как замена привязки устройства.
