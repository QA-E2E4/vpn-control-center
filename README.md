# VPN Control Center

Веб-панель управления OpenFlux, Happ/Xray Reality и AmneziaWG, документация
сопутствующего Windows-лаунчера панели и исходники OpenFlux Desktop для
Windows, macOS и Linux.

> Панель предназначена для собственного сервера и доступна только через
> localhost/SSH-туннель. Не публикуйте её в интернет без отдельной проверки
> аутентификации, TLS и модели доступа.

## Возможности

- Единый веб-интерфейс для собственных OpenFlux-, Happ/VLESS Reality- и
  AmneziaWG-доступов. Панель работает с уже развёрнутыми сервисами и не
  подменяет их клиентские приложения.
- Создание и администрирование профилей: выпуск QR/ссылки или конфигурационного
  файла там, где это поддерживает протокол; просмотр состояния сервиса,
  включение/отключение доступа, журнал действий и безопасное удаление.
- Реестры пользователей и устройств: назначение устройства владельцу,
  визуальное переименование и сводка по его устройствам. Удаление одного
  устройства не удаляет остальные; удаление владельца отзывает назначенные ему
  доступы во всех управляемых разделах.
- Персональные накопительные счётчики трафика из доступных источников OpenFlux,
  Xray и AmneziaWG. Если источник недоступен, панель показывает это явно;
  счётчики предназначены для наблюдения, а не для биллинга.
- Локальная адаптивная русскоязычная веб-страница без внешних CDN.
- Экспериментальный транспорт Telemost в серверной сборке OpenFlux 0.5.3:
  отдельная конференция нужна на каждую пару клиент/сервер; режим и
  совместимость конкретных клиентов проверяйте отдельно.

Ограничения: привязку ключа Happ к физическому устройству надёжно реализовать
без идентификатора/аттестации клиента нельзя. Панель не блокирует пользователей
по IP или числу TCP-соединений. Работа транспорта при ограничениях оператора
зависит от конкретной сети; гарантий обхода нет. Демо не управляет реальным
VPN. Тестовая эксплуатация на одном сервере не заменяет аудит безопасности.

## Возможности панели подробнее

| Раздел | Что можно делать |
|---|---|
| **OpenFlux** | Создавать отдельные подключения по ссылкам на поддерживаемые документы Mail.ru/Яндекса или конференцию Telemost; выдавать профиль в QR/ссылке; смотреть состояние индивидуальной службы и доступные счётчики; останавливать, запускать, перезапускать и удалять выбранный профиль. Настройки и данные профилей хранятся отдельно на сервере. |
| **Happ VPN** | Управлять пользователями существующего VLESS/Reality inbound Xray: создавать персональные credentials, выдавать VLESS-ссылку и QR, переключать доступ, выбирать поддерживаемый flow, менять подпись устройства и отзывать выбранный credential. Нужны совместимый Xray и включённые API/статистика/журнал; панель не привязывает ключ к физическому устройству и не применяет эвристику по IP или числу соединений. |
| **Amnezia VPN** | Управлять доступными peer AmneziaWG: создавать и отзывать peer, менять административные подписи, выдавать поддерживаемый Amnezia-конфиг/ссылку и QR. Экспортируемые параметры и семейство IP зависят от конкретного peer и конфигурации сервера. |
| **Пользователи и устройства** | Объединять устройства под владельцем, менять только отображаемые имена, видеть суммарный трафик и отдельно отзывать устройство или все устройства владельца. Действия удаления требуют подтверждения; для Xray также завершаются обнаруженные персональные TCP-сессии. |
| **Статус и журналы** | Просматривать состояние управляемых служб и профильные журналы/аудит. Данные статистики берутся из IPC OpenFlux, Xray Stats API или статистики WG, если она настроена и доступна. Это не журнал содержимого трафика и не гарантия доступности интернета через VPN. |

Для использования нужен backend на Linux VPS с настроенными соответствующими
OpenFlux/Xray/AmneziaWG-компонентами. Встроенный `--demo` показывает синтетические
данные локально и не управляет настоящими службами. Полное описание установки,
интеграций и ограничений — в [руководстве по развёртыванию](docs/DEPLOYMENT.md)
и [архитектуре](docs/ARCHITECTURE.md).

В экосистеме есть три разные части: веб-панель, Windows-лаунчер для SSH-доступа
к ней и VPN-клиент OpenFlux Desktop. Лаунчер открывает SSH-туннель к панели,
но не устанавливает VPN. Его исходники и инструкция находятся в
[`panel-launcher/`](panel-launcher/). OpenFlux Desktop, напротив,
импортирует пользовательские VPN-профили и запускает локальное ядро для
подключения к VPN-узлу. Ни один из этих клиентов не администрирует backend
панели и не получает её API-секреты. Подробное сравнение и ограничения лаунчера
описаны в [документации](docs/PANEL_LAUNCHER.md).

## Требования

- Linux VPS для production панели: systemd, Python 3.10+, OpenFlux core.
- Для соответствующих интеграций: Docker с уже настроенными Xray Reality
  и/или AmneziaWG. Панель не устанавливает и не перенастраивает их автоматически.
- Для демо и backend-тестов: Python 3.10+, `qrcode`, Node.js 20+.
- Для Windows Desktop: Windows 10/11, JDK 17+, Go, Git; Android Studio не нужен.

## Быстрый запуск демонстрации

В PowerShell или терминале проекта:

```powershell
py -3 -m venv .venv
.\.venv\Scripts\Activate.ps1
python -m pip install -r panel\requirements.txt
python panel\server.py --demo --data .\demo-data --port 8787
```

Откройте <http://127.0.0.1:8787>. Демо создаёт локальную SQLite и синтетические
профили. Оно не запускает `systemctl`, Docker, OpenFlux, Xray или AmneziaWG.
Остановить можно Ctrl+C.

## Production: безопасный доступ

Сначала изучите [SETUP.md](docs/SETUP.md) и [DEPLOYMENT.md](docs/DEPLOYMENT.md).
Production-панель должна слушать только `127.0.0.1`. Открывайте её локально
через SSH-туннель, например:

```powershell
ssh -N -L 8787:127.0.0.1:8787 admin@your-vps.example.net
```

Не запускайте пример production unit, пока не проверены пути, отдельные
системные пользователи, права на socket/данные и интеграции конкретного VPS.
Панель имеет административные права на выбранные серверные действия.

## Windows Desktop

Клонируйте проект вместе с upstream submodules:

```powershell
git clone --recurse-submodules https://github.com/QA-E2E4/vpn-control-center.git
```

Если репозиторий уже клонирован без них, выполните
`git submodule update --init --recursive` из его корня.

```powershell
cd windows-client
.\gradlew.bat :shared:jvmTest
.\gradlew.bat -PwindowsPackage=true :desktopApp:packageMsi
```

Для запуска без сборки ядра: `.\gradlew.bat -PskipCore=true :desktopApp:run`.
Полные инструкции — [WINDOWS_APP.md](docs/WINDOWS_APP.md).

Desktop-клиент хранит импортированные VPN-профили на компьютере и запускает
ядро OpenFlux локальным дочерним процессом. Он подключается по выбранному
профилю и не управляет backend панели. Встроенный прокси-режим и системный
режим полного туннеля зависят от ОС и транспорта; экспериментальные транспорты
могут иметь дополнительные ограничения.

## Проверки

```powershell
python -m pip install -r panel\requirements.txt
python -m unittest discover -s panel\tests -p "test_*.py" -v
node panel\tests\frontend.test.js
node --check panel\static\app.js
```

GitHub Actions повторяет эти проверки и запускает JVM-тесты/сборку Windows MSI.
Результаты каждого запуска смотрите во вкладке Actions.
